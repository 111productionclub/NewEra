- **Каждое архитектурное решение записывать в `DECISIONS.md`** (формат: вопрос, варианты, решение, почему). Это источник истины по архитектуре и материал для таймлайна видео для соцсетей. Нумерация D-XX сквозная; последняя запись на данный момент D-06.

## Команды

Все команды запускаются из `frontend/`. Менеджер пакетов — pnpm (версия зафиксирована в `package.json` через `packageManager`).

```bash
pnpm install     # установка зависимостей
pnpm dev         # dev-сервер, http://localhost:3000
pnpm build       # продакшен-сборка
pnpm lint        # ESLint
pnpm exec tsc --noEmit   # проверка типов без сборки
```

Тестов фронтенда пока нет. Бэкенд (из `backend/`): `.venv/bin/python manage.py runserver` и `.venv/bin/python manage.py test`, подробности в `backend/README.md`.

## Архитектура

Монорепо одного проекта: `frontend/` (Next.js 16, React 19, TypeScript strict, Tailwind 4, App Router, папка `src/`). Бэкенд (`backend/`, Django + DRF, пока SQLite) создан: админка товаров с загрузкой фото и API на чтение (D-17), фронтенд к нему ещё не подключён. Запуск и детали в `backend/README.md`. `legacy/` — старый статичный прототип (HTML/CSS/JS), оставлен для сравнения «было → стало» и будет удалён; не развивать и не ориентироваться на его структуру.

Цель: лендинг с товарами. В карточке товара есть ссылка на VK (поле `vkUrl`). Страница товара — один шаблон по адресу `/products/[slug]`, данные подставляются из источника. Оплата вне scope. Корзины не будет (D-14): кнопка «Купить в VK» на странице товара копирует текст заказа в буфер и открывает диалог сообщества VK (D-08). Сайт строится так, чтобы позже стать полноценным магазином.

Поток данных, который нужно держать в голове (понятен только по нескольким файлам):

- `src/types/product.ts` — тип `Product`. Задуман таким, каким его потом отдаст Django API, чтобы при подключении бэкенда менялся только источник данных.
- `src/data/products.ts` — массив `products: Product[]`, пока заглушка вместо API.
- `src/components/product/` — компоненты получают `Product` через пропсы и не знают, откуда он пришёл.
- `src/app/page.tsx` — главная, собирает сетку карточек из `products`.

Принципы (решение D-05):
- Данные не живут в компонентах.
- В данных товара только факты. Флаги оформления (`dark`, `background`, `statusPixel` из старого прототипа) в тип сознательно не добавлены.
- Server Components по умолчанию; `"use client"` только там, где нужна интерактивность (галерея, выбор размера).
- Алиас импорта `@/*` указывает на `src/`.
- Статика и картинки лежат в `frontend/public/`; пути в коде пишутся от корня (`/img/bomber.jpg`).

## Соглашения

- Файлы компонентов называются с большой буквы, как сам компонент (`ProductCard.tsx`): на Vercel (Linux) регистр в путях важен.
- Именованный экспорт для компонентов, `export default` только для страниц Next.js.
- Список элементов в JSX всегда с `key` (используем `id` товара).
- Картинки через `next/image`, у каждой осмысленный `alt`.
- Ссылка на VK: `target="_blank" rel="noopener noreferrer"`; у товаров со статусом `sold-out` отключена.

- Не использовать `git add .`: коммитить файлы по именам.
