# NewEra

Лендинг магазина одежды.

> Архитектура пересобирается с нуля. Актуальные решения — в `DECISIONS.md` (источник истины). Ниже описан старый статичный прототип; разделы про структуру, принципы и план рефакторинга устарели и будут переписаны по мере решений.

**Стек (D-01):** Next.js (App Router) + React + TypeScript + Tailwind; GSAP/Motion; бэкенд позже Django + DRF + Postgres; Vercel.

**Правило работы:** код пишет владелец проекта, Claude ревьюит и советует. Каждое архитектурное решение фиксируется в `DECISIONS.md` (для таймлайна видео).

## Текущая задача (scope)

Сейчас сайт — **просто лендинг с товарами**. Внутри карточки товара есть **ссылка на VK**, по которой покупатель связывается / покупает.

**Страница товара (`product.html`) нужна.** Это один шаблон: разметка статична, данные подставляются из `js/data/products.js` по `?id=`. Сайт строится так, чтобы позже превратить его в полноценный магазин, поэтому шаблон страницы и карточки не содержат захардкоженных данных товара.

Вне scope (пока не делаем): корзина, модалка заказа, форма, отправка заказов, бэкенд. Существующий код корзины и модалки в `js/main.js` считается устаревшим и при рефакторинге удаляется или выносится отдельно, не развивается.

## Принципы архитектуры

- Один модуль — одна ответственность. Данные, логика и отображение не смешиваются.
- Данные товаров живут отдельно от кода (`js/data/products.js`), позже можно заменить на JSON/API.
- Поток данных односторонний: данные → render.
- В данных товара только факты (название, цена, статус, картинки, ссылка VK). Флаги отображения (например `hideOnMobileRelated`) в данные не кладём — это задача CSS.
- Все цвета, шрифты, размеры — в CSS-переменных (`:root`).
- Mobile-first медиа-запросы.
- HTML собираем через `<template>` или шаблонные строки, не конкатенацией. Пользовательский/внешний текст всегда экранируем (`escapeHtml`).
- Без фреймворка. Если появятся фильтры, оплата, кабинет или админка — переходить на Vite + React или Astro.

## Целевая структура

```
NewEra/
├── index.html
├── product.html            # шаблон страницы товара, данные подставляются из products.js
├── assets/ (img, icons)
├── css/
│   ├── base.css            # reset, :root переменные, типографика
│   ├── layout.css          # header, footer, grid
│   ├── components/
│   │   ├── card.css
│   │   └── gallery.css
│   └── style.css           # только @import перечисленного
└── js/
    ├── main.js             # точка входа
    ├── data/products.js    # массив товаров (включая vkUrl)
    ├── utils/format.js     # formatPrice, escapeHtml
    ├── components/
    │   └── card.js         # разметка карточки со ссылкой на VK
    └── pages/
        ├── home.js
        └── product.js
```

JS подключается как `<script type="module" src="js/main.js">`. Модули не работают по `file://` — запускать через `npx serve` или Live Server.

## Правила для ссылки на VK

- Поле `vkUrl` в данных каждого товара.
- Ссылка: `target="_blank" rel="noopener noreferrer"`.
- Ссылка есть и в карточке на главной, и на странице товара (кнопка вместо «В корзину»).
- Для sold out товаров кнопка/ссылка отключена или заменена на «Sold Out».

## План рефакторинга (по шагам)

1. Вынести `products.js` и `format.js` из `main.js`.
2. Разбить `main.js` на `components/` и `pages/`; удалить корзину и модалку заказа.
3. Сделать `product.html` чистым шаблоном (заголовок, цена, галерея, размеры, описание — из данных), без захардкоженного контента.
4. Добавить `vkUrl` в данные и ссылку в карточку.
5. Разрезать `style.css` (сейчас ~1240 строк) на `base`, `layout`, `components/*`.
6. Убрать дублирование шапки, если проект вырастет.

## Задел под полноценный магазин

- Структура товара должна допускать расширение: `id`, `name`, `price`, `status`, `image`, `gallery`, `sizes`, `description`, `vkUrl`. Новые поля добавляем, существующие не переименовываем.
- Корзину и оформление заказа добавим позже отдельным модулем `state/cart.js` и `components/order-modal.js`, не трогая шаблоны страниц.

## Соглашения

- CSS: БЭМ (`block__element--modifier`).
- Язык интерфейса: русский (`<html lang="ru">`), комментарии в коде — по необходимости, кратко.
- Доступность: `aria-label` у кнопок-иконок, осмысленные `alt` у картинок товаров.
