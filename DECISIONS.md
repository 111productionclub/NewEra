## D-01 · Стек · 2026-10-17
Вопрос: на чём строим NewEra и будущие студийные проекты.
Варианты: A) чистые HTML/CSS/JS; B) Vite + vanilla JS; C) Astro; D) Next.js + React + TypeScript.
Решение: Next.js (App Router) + React + TypeScript + Tailwind CSS; анимации GSAP / Motion (+ Lenis для скролла, Three.js при необходимости); бэкенд позже на Django + DRF + Postgres; деплой на Vercel.
Почему: студия хочет делать сильные проекты, поэтому нужны стандартные профессиональные инструменты, на которых можно взять любой заказ. Промежуточный этап на vanilla JS пропускаем. Владелец проекта любит Django, поэтому он остаётся бэкендом.
Отброшено: vanilla/Vite (учит основам, но не стек для заработка), Astro (хорош для контента, но уже, чем нужно студии).

## D-02 · Структура репозитория · 2026-10-17
Вопрос: как организовать код фронта и будущего бэкенда в условиях команды из 3 человек и 2 проектов.
Варианты: A) один репозиторий на проект с папками frontend/ и backend/; B) отдельные репозитории под фронт и бэк; C) общий монорепо студии (Turborepo/Nx).
Решение: A. Один репозиторий на проект, внутри frontend/ и backend/. Общий код между проектами пока не выносим. Пакетный менеджер pnpm, хостинг кода на GitHub, main защищён, работа через feature-ветки и pull request с ревью.
Почему: команда небольшая, проекты независимы (свои релизы, заказчики, доступы). Инструменты монорепо окупаются при 5+ проектах с общим кодом. Если появится заметное дублирование, вынесем общий пакет (например studio-ui).
Отброшено: B (лишний оверхед на два репозитория одного продукта), C (избыточно для 2 проектов).
